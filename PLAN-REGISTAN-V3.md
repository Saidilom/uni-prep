## Группа 7 — Rasch-скоринг (Phase 12/34, обязателен в MVP) — реализовано 25.08.2026

- [x] **36.** Спецификация зафиксирована как исполняемый код с подробными комментариями в `src/lib/rasch.ts` (не отдельный markdown-документ — код и есть спецификация): модель `P(correct) = exp(θ_n - b_i) / (1 + exp(θ_n - b_i))`, ограничение идентифицируемости `mean(b_i) = 0`, оценка через Joint Maximum Likelihood Estimation (JMLE) последовательными (Gauss-Seidel) проходами Ньютона-Рафсона — сначала все item difficulty по текущим θ, потом все person ability по свежим b. Экстремальные баллы (0 или 100% у человека/вопроса) обрабатываются стандартной поправкой Wright & Panchapakesan (1969) — сдвиг на 0.3 балла от края, иначе оценка уходит в бесконечность. Дополнительно (важная находка в процессе — на малых/разреженных выборках, которые будут в проде на старте, одной этой поправки недостаточно: подтвердил численно на тестовых данных, что без демпфирования шаг Ньютона-Рафсона может уйти вразнос до ±10⁵ при почти разделимых данных) — добавил плавное tanh-демпфирование шага и жёсткий clamp параметров в [-8, +8] логитов (как в Winsteps). Логику проверил отдельным numeric-скриптом (не автотест в репозитории, разовая проверка): на выборке 30×10 с шумом и пропусками — корреляция оценок с истинными параметрами 0.93, сходится за 8 итераций; на выборке с гарантированно экстремальными баллами — оценки остаются конечными и в разумных пределах.
- [x] **37.** Item difficulty (`b_i`) и person ability (`θ_n`) — параметры модели, оба возвращает `estimateRasch()`. Матрица student × item строится в `/api/rasch/recalculate` из `mock_answer_details` (person = `mock_results.id`, item = `mock_questions.id`, значение = `is_correct`) — сознательно только для Mock, не для Placement: у Placement с Группы 4 никакой ответ по вопросам не сохраняется вообще (решение "никому, разово"), так что построить матрицу для него в принципе нечем.
- [x] **38.** Отдельный сервис расчёта — не встроен в `submit_mock`, а отдельный роут `/api/rasch/recalculate` (миграция `014_rasch_scoring.sql` + `src/lib/rasch.ts`), т.к. калибровка item difficulty требует ответов ВСЕХ, кто проходил этот Mock-тест, а не только текущего человека — при каждой новой попытке пересчитывается весь тест целиком (fire-and-forget вызов из `mock/[id]/page.tsx` сразу после успешного `submit_mock`, не блокирует показ результата ученику).
