## ✅ Решения (зафиксировано 25.08.2026)

1. **Diagnostic (Placement)**: ученику показываем только итоговый %. Детальный разбор по вопросам никому не показывается и в БД не сохраняется — это одноразовый расчёт (посчитали % и забыли). → Группа 4 (24–25) разблокирована.
2. **Монетизация**: остаёмся на разовой покупке доступа к одному Mock-тесту. Подписки (Plan/Subscription) не делаем. → Группа 5 (26–31) переопределена под реальные платежи вместо подписок, разблокирована.
3. **Роль «Учитель»**: нужна. Учитель создаёт классы, ищет и добавляет учеников в свои классы по Student ID, назначает им тесты. → Группы 2–3 (9–23) разблокированы.
4. **Провайдер оплаты**: все три — Payme, Click, Uzum. Делаем структуру интеграции (env-переменные под ключи каждого провайдера, отдельные webhook-роуты с проверкой подписи, UI выбора провайдера на чекауте) уже сейчас; реальные значения ключей пока не заводим — при нажатии "Оплатить" провайдер корректно вернёт "оплата недоступна" вместо мок-подтверждения, без крашей.
5. **Rasch-скоринг**: обязателен, остаётся в MVP без отсрочки. → Группа 7 (36–38) больше не низкий приоритет.
6. **Старый контент**: удаляем всё, что не входит в `план 100` — `firebase.ts`, `/test/[id]`, `/subject/[id]`, старую реализацию `/classes` + `class-utils.ts` (заменяется новой схемой из Группы 2). См. задачу 46.
