# Дизайн-система Registan

Единый референс того, что уже принято и реализовано в коде. Не источник новых идей — фиксация решений, чтобы каждая следующая страница переделывалась одинаково, а не заново придумывалась.

## Цвета

**Только светлая тема.** Тёмная тема была полностью удалена по прямому запросу пользователя: `ThemeToggle`-компонент, переключатель в топбаре, скрипт в `layout.tsx` (ставил класс `dark` до гидратации), логика форс-сброса на `/login`/`/join`/`/onboarding`, `.dark { ... }` блок переменных в `globals.css`, `APP_THEME_KEY` — всё удалено. `darkMode: ["class"]` в `tailwind.config.ts` **намеренно оставлен как есть** — если его убрать или сменить стратегию, оставшиеся по коду `dark:`-варианты Tailwind начнут реагировать на системную тему ОС вместо того, чтобы быть мёртвым кодом. Не добавлять переключатель темы обратно без явного запроса.

**Канонические 5 цветов сайта — заданы пользователем, менять только по его запросу:**

| Hex | Роль на сайте |
|---|---|
| `#5085A5` | `--primary` |
| `#8FC1E3` | не используется сейчас (был dark-вариантом primary) |
| `#31708E` | `--brand-blue-ink` — цвет заголовков секций и текста поверх мягких бейджей |
| `#2B7A78` | `--brand-olive` (название переменной осталось прежним, значение — этот бирюзовый) — второй акцент, только точечно (плюс большая заливка сайдбара, см. ниже) |
| `#F7F9FB` | `--background` — фон страницы |

Никаких других «брендовых» тонов (других синих/фиолетовых и т.п.) в интерфейс не добавлять — только эти пять через токены ниже. Семантические статусные цвета (успех/ошибка/предупреждение — эмеральд/красный/янтарь, см. ниже) — отдельная категория, не бренд, их это ограничение не касается.

Все цвета живут как CSS-переменные (HSL-тройки) в `src/app/globals.css`, потребляются через `hsl(var(--x))` в `tailwind.config.ts`. Не хардкодить hex/`blue-600`-литералы — только токены.

| Переменная | Значение | Роль |
|---|---|---|
| `--primary` / `--ring` | `#5085A5` | Единственный акцент действия: кнопки, ссылки, фокус-кольца, активные состояния. Не смешивать с `bg-foreground`/`bg-blue-*` литералами. |
| `--brand-blue-soft` / `--brand-blue-ink` | светлый тон / `#31708E` | Мягкие бейджи и их текст (цена, статус, CEFR-балл) — `bg-[hsl(var(--brand-blue-soft))] text-[hsl(var(--brand-blue-ink))]`. |
| `--brand-olive` / `-soft` / `-ink` | `#2B7A78` + варианты | Второй акцент **только** для точечных бейджей/декоративных штрихов. Никогда не заменяет `--primary`. |
| `--background` | `#F7F9FB` (едва охлаждённый белый) | Фон страницы, сайдбара (кроме исключения ниже), топбара — **не** для карточек контента. |
| `--card` | чистый белый `#FFFFFF` | Фон карточек контента — сознательно отличается от `--background`, чтобы карточка визуально приподнималась над страницей, а не сливалась с ней. |
| `--destructive` | красный | Только необратимые/деструктивные действия (удалить аккаунт, выйти). |

Статусные цвета успеха/предупреждения/ошибки (эмеральд/янтарь/красный) — не токены темы, а фиксированные Tailwind-литералы через общий хелпер `accuracyColor()` (см. «Хелперы» ниже) — не изобретать свои пороги в новом файле.

**Главная (`src/app/(dashboard)/page.tsx`) — точечное исключение, `--primary` не используется вообще.** По прямому запросу пользователя весь голубой (`#5085A5`) на этой странице заменён на `--brand-blue-ink` (`#31708E`, темнее): кнопки (`bg-[hsl(var(--brand-blue-ink))] text-white` вместо `bg-primary text-primary-foreground`), ссылки (`text-[hsl(var(--brand-blue-ink))]` вместо `text-primary`), и часть иконок-блоков — теперь сплошная заливка ink-цветом (`bg-[hsl(var(--brand-blue-ink))] text-white`), а не мягкий тон 10%. Это решение пока действует только для Главной — на других страницах по умолчанию всё ещё `--primary`, пока не попросят перенести и там.

**Платный контент — исключение из правила «один primary-акцент».** Кнопка покупки/оплаты Mock-теста (`Купить`/`Enroll`) и бейдж цены — не `--primary` (синий), а красный (`bg-red-600 text-white hover:bg-red-700` для кнопки, `bg-red-50 text-red-600 dark:bg-red-950/40 dark:text-red-300` для бейджа цены) — это осознанно другой, «горячий» акцент, чтобы платный тест визуально бросался в глаза на фоне спокойного синего интерфейса. Тот же красный уже используется для статуса `locked` в `MOCK_STATUS_COLOR` (`src/lib/status-colors.ts`) — держать это соответствие: «недоступно/нужно купить» = красный, «можно начать» = `--primary`.

## Каркас страницы (сайдбар/топбар/контент)

`src/app/(dashboard)/layout.tsx` + `src/components/page-wrapper.tsx`. Топбар и область контента — на `bg-background`, без отступов между ними и без обёртки контента в отдельную карточку (было раньше: `PageWrapper` рисовал `rounded-t-3xl border shadow-md` вокруг всей страницы — визуально «коробка», плавающая на сером фоне, с явным швом между меню и контентом — от этого отказались). `PageWrapper` только задаёт внутренние отступы (`px-6 sm:px-8`, `pt-6 sm:pt-8`), фона/рамки/тени не рисует. Не возвращать сюда рамку/фон/тень у обёртки — конкретные карточки контента (`bg-card`) сами приподнимаются над `bg-background` за счёт разницы токенов (см. выше), этого достаточно.

**Сайдбар (`src/components/sidebar.tsx`) — исключение, осознанно цветной.** Фон — `bg-[hsl(var(--brand-olive))]` (`#2B7A78`) — как цветной сайдбар у большинства дашборд-приложений. Весь текст/иконки внутри — на белом: активный пункт `bg-white/15 text-white`, неактивный `text-white/65 hover:text-white hover:bg-white/10`, разделители `border-white/10`, лого — `brightness-0 invert` (та же техника, что в `HeroBanner`/`AuthShell`). Это единственное место на сайте, где `--brand-olive` — большая заливка, а не точечный акцент.

## Типографика

Шрифт — **Golos Text** (`--font-golos-text`, подключен в `src/app/layout.tsx`, поддерживает кириллицу). Менять не нужно.

- H1 страницы: `text-3xl font-bold tracking-tight text-foreground sm:text-4xl` (чёрный/`text-foreground`, не цветной — держит верхний уровень иерархии).
- Заголовок секции (подзаголовок блока контента, напр. «Premium Mocks», «Мои группы», не заголовок карточки/бейджа и не чьё-то имя): `text-xl font-bold tracking-tight sm:text-2xl text-[hsl(var(--brand-blue-ink))]` — цветной, чтобы бренд-палитра была заметна на странице, а не только на кнопках. Правило добавлено после жалобы, что страница выглядела монохромной, несмотря на применённые токены цвета — токены были на месте, но реально нигде не были видны, кроме мелких акцентов.
- Eyebrow-лейбл (маленькая подпись над значением): `text-[10px] font-bold uppercase tracking-widest text-muted-foreground`
- Тело: `text-sm text-muted-foreground` (описания), `text-sm font-semibold text-foreground` (значимый текст в карточках)

## Радиус контейнеров

Не смешивать уровни — у каждого своя роль:

| Radius | Где |
|---|---|
| `rounded-3xl` | Hero-баннеры, финальный экран результата теста, редко — крупные пустые состояния |
| `rounded-2xl` | Стандартная карточка контента / строка списка (доминирующий паттерн) |
| `rounded-xl` | Кнопки, пилюли, чипы, мелкие бейджи, инпуты |
| `rounded-lg` | Только строки навигации в сайдбаре |

## Кнопки — три уровня

```
Primary:      rounded-xl bg-primary text-primary-foreground font-semibold shadow-sm
              transition-all hover:opacity-90 active:scale-[0.97]

Secondary:    rounded-xl border border-border bg-card text-foreground
              hover:bg-muted transition-colors

Destructive:  rounded-xl bg-destructive/10 text-destructive hover:bg-destructive/20
              (сплошной bg-destructive — только для необратимых действий:
              удалить аккаунт и т.п.)
```

Primary — всегда одна и та же кнопка визуально, независимо от страницы («Начать», «Купить», «Сохранить», «Let's start»-подобные CTA). Не создавать локальные варианты с другим цветом/радиусом.

## Переиспользуемые хелперы — использовать, не дублировать

| Хелпер | Файл | Что делает |
|---|---|---|
| `cn()` | `src/lib/utils.ts` | Слияние Tailwind-классов с правильным приоритетом (`clsx` + `tailwind-merge`) — обязателен, если компонент принимает `className` и должен позволять переопределять дефолтные классы. |
| `pluralizeRu()` | `src/lib/pluralize-ru.ts` | Русское склонение по числу (1/2-4/5+) — не писать `count === 1 ? "x" : "y"` руками. |
| `accuracyColor()`, `MOCK_STATUS_COLOR` | `src/lib/status-colors.ts` | Единая палитра успех/предупреждение/ошибка и статусов теста (доступен/заблокирован/пройден). |
| `<HeroBanner>` | `src/components/hero-banner.tsx` | Градиентный hero-блок (используется на Главной и в Профиле) — не копировать градиент+паттерн вручную в новый файл. |

## Чек-лист: как переделать очередную страницу

1. Замени любые `bg-foreground`/`text-background` на активных кнопках → `bg-primary`/`text-primary-foreground`.
2. Замени сырые `bg-blue-*`/`text-blue-*`/`border-blue-*` литералы → `bg-primary`/`text-primary` либо `hsl(var(--brand-blue-soft/ink))` для мягких бейджей.
3. Проверь radius каждого контейнера по таблице выше — кнопка не должна быть `rounded-2xl`, карточка не должна быть `rounded-xl`.
4. Статусные/акцентные цвета — через `accuracyColor()`/`MOCK_STATUS_COLOR`, не новыми литералами.
5. Повторяющиеся числительные ("X учеников/ученика") — через `pluralizeRu()`.
6. Если несколько мест используют один и тот же составной блок (градиент-hero, карточка-статистика) — вынести в `src/components/`, не копировать JSX.
7. После правок: `npx tsc --noEmit`, `npm run lint`, при необходимости `npm test`.
